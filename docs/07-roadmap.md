# 07 · M1/M2/M3 路线图

本页区分已提交代码、已验证范围和未完成工作。方案参考用户提供的配置稿，但按本仓库现有复用边界收缩：不把 hidden golden TB 放进共享 State，不复制大文件进 checkpoint。

| 阶段 | 工作 | 完成判据 |
|---|---|---|
| M1a：闭环代码 | 已接前置自检 TB、Graph 状态调度、旧服务复用、只读参考文件工具和可选 LangSmith 追踪 | 离线主路径、Docker 回归与真实模型单题烟测已过；全量对照仍待完成 |
| M1b：可靠性 | 补全失败/修复/预算测试、Graph 跨进程恢复、契约时序/握手字段 | 每条关键分支有回归，恢复不会重复执行副作用 |
| M1c：对照 | 冻结配置，重跑同一 Human v2 集合的旧、新入口，并隔离 TB 变量 | 逐题差异和功能/成本报告可复现，退化原因可定位 |
| M2：增强 | 本地协议文档 RAG、VCD 摘要、Yosys 综合门禁 | 三项分别有安全边界、测试与单变量结果 |
| M3：多模块 | Master 分解、并行 Coder、Assembler 顶层连接 | 子模块和顶层集成都可验证，接口错误可定位 |

新图保留“先一个候选、静态失败或 <75 分时生成新候选、功能失败优先修复”的旧策略；当前 CLI 由 `--max-repairs` 控制修复预算，Human v2 批量默认 2 次，实验建议显式指定 3 次。M2/M3 不在 M1 的完成声明中。

工程交付还包括：中文 README、按主题组织的 docs、可执行命令、自动化回归、GitHub PR 与检查结果。旧入口和旧报告在新入口对照通过前保留。
