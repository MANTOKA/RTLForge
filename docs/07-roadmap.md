# 07 · M1/M2/M3 路线图

本页列任务与验收，不将计划项算作已完成。实施基线来自用户提供的“LangGraph State / 节点流转 / 消融变量”配置；其中 `golden_tb_files` 改为 Verifier 私有引用，成对实验使用两个任务 ID，原因见[架构](03-architecture.md)。

| 阶段 | 工作 | 完成判据 |
|---|---|---|
| M1a：契约与 TB | 扩展 `SpecIR` 的时钟/复位/握手/时序约束和 `coding_style_constraint`；接通前置自检 TB | 规格校验、TB 不读取 DUT、Coder 不读取完整 TB 的测试通过 |
| M1b：图与工具 | 新增 LangGraph 入口，复用旧 Agent/EDA/评分/Memory；独立 checkpoint、受限只读工具与 LangSmith 追踪 | 成功、静态失败、功能失败、修复、预算耗尽和中断恢复可重放 |
| M1c：对照 | 冻结配置，重跑同一 Human v2 集合的旧、新入口 | 逐题差异和功能/成本报告可复现，退化原因可定位 |
| M2：增强 | 本地协议文档 RAG、VCD 摘要、Yosys 综合门禁 | 三项分别有安全边界、测试与单变量结果 |
| M3：多模块 | Master 分解、并行 Coder、Assembler 顶层连接 | 子模块和顶层集成都可验证，接口错误可定位 |

M1 保留当前“先一个候选、静态失败或 <75 分时生成新候选、功能失败优先修复”的策略；默认三轮修复。M2/M3 不在 M1 的完成声明中。代码目录只在对应阶段增设，避免空壳模块。

工程交付还包括：中文 README、按主题组织的 docs、可执行命令、自动化回归、GitHub PR 与检查结果。旧入口和旧报告在新入口对照通过前保留。
